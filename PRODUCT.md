# «Ходи Броди»: как довести прототип до зрелого продукта

Роль: Senior Product Designer + Product Manager.
Вводная: есть городская афиша и агрегатор мест. ЦА — жители города, ищущие досуг, и локальные организаторы. Главное действие — **найти событие/место и перейти к билетам/регистрации**.
Ограничение соблюдено: палитра не менялась, все 19 токенов — из исходного проекта.

---

## 1. Диагноз «сырости»: 5 причин

### 1.1. В продукте нет афиши — есть только игра

Заявлено «городская онлайн-афиша», но на главной нет ни одного события: ни даты, ни времени, ни цены, ни организатора. Пять карточек мест — это каталог, а не афиша. Пользователь с задачей «куда пойти в субботу» не может её решить: нечего выбрать, нечего сравнить, некуда перейти за билетом.

**Что это ломает:** главное целевое действие (переход к билетам) физически отсутствует — нет CTA «купить билет», нет цены, нет привязки ко времени.

### 1.2. Продукт говорит о механике, а не о выгоде

Первый экран объясняет, как устроена игра («Броди. Выполняй. Копи.»), но не отвечает на вопрос пользователя «что я получу и где». Ценность «бутсов» понятна только после трёх секций: сначала игра, потом обмен, потом лавка. Новичок должен прочитать ~2000 слов, чтобы понять, зачем ему это.

**Проверка:** если закрыть заголовок, остальные блоки не отвечают на вопрос «куда пойти сегодня». Они отвечают на «как работает наша механика».

### 1.3. Нет плотности данных — и поэтому нет доверия

В карточке места есть только название и категория. Нет: когда открыто, сколько стоит, сколько людей идут, рейтинга, отзывов, организатора, «до скольки». Зрелая афиша выигрывает **плотностью решения** — за 10 секунд видно дату, цену, место и статус. Сейчас эти 10 секунд уходят на переходы и догадки.

**Симптом шаблона:** одинаковая сетка карточек без иерархии «что важно в этом типе контента». У события важны дата и цена, у места — адрес и режим работы. Сейчас у всех одно и то же.

### 1.4. Нет состояний — интерфейс врёт о готовности

У прототипа нет: загрузки, пустых состояний с действием, ошибок, «ничего не найдено», «событие прошло», «билетов нет». Пользователь не понимает, что система жива: после фильтра просто исчезают карточки — без объяснения. Это самый заметный признак недоделанности: **зрелый продукт объясняет каждое «пусто»**.

### 1.5. Нет социального доказательства и срочности

Ноль сигналов «здесь реальные люди»: ни количества идущих, ни «осталось 12 мест», ни отзывов, ни «выбор редакции», ни «друзья идут». Афиша без социального доказательства читается как каталог из базы данных. Плюс нет срочности: даты не подсвечены («завтра», «последний день»), нет обратного отсчёта — нечего решать сейчас.

## 2. Быстрые победы (2–4 часа каждая)

| № | Что | Почему работает | Статус |
|---|---|---|---|
| 1 | **«Идут N человек» + редакционная метка** на карточке события | Соцдоказательство + кураторство: снимает выбор с пользователя и сигналит «это живое» | ✅ в коде |
| 2 | **Поиск с мгновенными подсказками** (события + места, стрелки, `/`) | Убирает главный барьер: «а есть ли у вас вообще Х». Пустой результат теперь объясняется подсказкой | ✅ в коде |
| 3 | **«Добавить в календарь» (.ics)** | Превращает интерес в обязательство без регистрации и бэкенда. 30 строк кода, ощутимая польза | ✅ в коде |
| 4 | **Умные подписи дат:** «Сегодня», «Завтра», «пт, 28 ноя» вместо ISO | Убирает когнитивную работу: пользователь не считает дни в голове | ✅ в коде |
| 5 | **Пустые состояния с действием** вместо пустого экрана | Каждое «пусто» объяснено и даёт выход: сбросить фильтр, расширить период, посмотреть избранное | ✅ в коде |

Что ещё стоит сделать в тот же бюджет, но не вошло в код: скелетоны карточек на 400 мс при смене фильтра, микроанимация появления ленты (stagger 40 мс), бейдж «осталось N мест» на основе поля `capacity`, подсказка «нажмите / для поиска» при первом визите.

## 3. Продуктовое расширение (4–5 функций)

### 3.1. Афиша с периодом и умными фильтрами — **реализовано**
Сегодня / Завтра / Выходные / Неделя + категории с количеством + «Бесплатно» + «С детьми» + «Избранное». Это ядро продукта: без него нет ни афиши, ни перехода к билетам. Категории показывают счётчик, чтобы фильтр не приводил в пустоту.

### 3.2. «Мой план на выходные» — сохранение и календарь — **реализовано**
Избранные события сохраняются в `localStorage`, фильтр «Избранное» собирает их в один список, любое событие выгружается в `.ics`. Следующий шаг: собирать 2–4 события в маршрут с временными слотами и проверкой пересечений.

### 3.3. Карточка события как отдельная страница (следующий приоритет)
Сейчас деталь открывается в подборке дня. Нужен URL `event.html?id=…`: описание, программа, организатор, правила возврата, схема зала/площадки, «похожие события», отзывы. Это то, что индексирует поиск и на что ведут рекламные ссылки организаторов.

### 3.4. Кабинет организатора (вторая ЦА, которой сейчас нет вообще)
Форма публикации события → модерация → статистика (просмотры, клики «купить», конверсия), управление квотой и промокодами. Без этого афиша не масштабируется: контент нужно кому-то заводить. Минимум: 1 экран «Мои события» + 1 форма + 4 метрики.

### 3.5. Напоминания и «что рядом сейчас»
Push/email за 3 часа до события и утренняя сводка «сегодня в городе». Плюс режим «я в центре»: события в радиусе 15 минут пешком. Для демо — блок «Сейчас рядом» на главной, сортировка по времени начала.

## 5. Код трёх главных улучшений

Все три реализованы в текущем стеке (HTML + CSS + ванильный JS), без зависимостей и без изменения палитры.

### 5.1. Афиша: данные, период, фильтры, карточки

**`data.js`** — 11 демо-событий; даты считаются от текущего дня, поэтому «Сегодня / Завтра / Выходные» никогда не устаревают:

```js

    going: 214, editorPick: true, description:'…' },
  // …
```

**`app.js`** — фильтрация по периоду и категориям со счётчиками:

```js
function eventInPeriod(event) {
  const offset = dayOffset(new Date(event.start));
  if (offset < 0) return false;
  if (afisha.period === 'today') return offset === 0;
  if (afisha.period === 'tomorrow') return offset === 1;
  if (afisha.period === 'weekend') return isWeekend(new Date(event.start)) && offset <= 7;
  return offset <= 7;
}

function visibleEvents(ignoreSaved) {
  return events
    .filter(e => e.city === afisha.city)
    .filter(e => afisha.category === 'Все' || e.category === afisha.category)
    .filter(e => !afisha.free || e.price === 0)
    .filter(e => !afisha.kids || e.age === '0+' || e.age === '6+')
    .filter(e => ignoreSaved || !afisha.savedOnly || afisha.saved.includes(e.id))
    .filter(eventInPeriod)
    .sort((a, b) => new Date(a.start) - new Date(b.start));
}
```

**Умные подписи дат** — снимают с пользователя счёт дней:

```js
function dayLabel(date) {
  const offset = dayOffset(date);
  if (offset === 0) return 'Сегодня';
  if (offset === 1) return 'Завтра';
  return `${WEEKDAYS[date.getDay()]}, ${date.getDate()} ${MONTHS[date.getMonth()]}`;
}
```

Фильтры хранятся в `localStorage` (`brodi-afisha-v1`): город, период, категория, бесплатные, с детьми, избранное.

### 5.3. Календарь без бэкенда (.ics по RFC 5545)

```js
function downloadCalendar(event) {
  const start = new Date(event.start);
  const end = new Date(start.getTime() + event.duration * 60000);
  const stamp = d => d.toISOString().replace(/[-:]/g, '').replace(/\.\d{3}/, '');
  const escape = v => String(v).replace(/\\/g, '\\\\').replace(/;/g, '\\;')
                            .replace(/,/g, '\\,').replace(/\n/g, '\\n');

  // RFC 5545: строки > 75 октетов переносятся с ведущим пробелом,
  // иначе строгие клиенты (Outlook) отклоняют файл
  const fold = line => { /* … */ };

  const lines = [
    'BEGIN:VCALENDAR', 'VERSION:2.0',
    'PRODID:-//Hodi Brodi//Afisha//RU', 'CALSCALE:GREGORIAN',
    'BEGIN:VEVENT',
    `UID:${event.id}@hodi-brodi.demo`,
    `DTSTAMP:${stamp(new Date())}`,
    `DTSTART:${stamp(start)}`, `DTEND:${stamp(end)}`,
    `SUMMARY:${escape(event.title)}`,
    `LOCATION:${escape(`${event.venue}, ${event.address}`)}`,
    `DESCRIPTION:${escape(event.description)}`,
    'END:VEVENT', 'END:VCALENDAR'
  ];

  const blob = new Blob([lines.map(fold).join('\r\n')], { type: 'text/calendar;charset=utf-8' });
  // … скачивание через <a download>
}
```

Проверено: файл валиден, максимальная длина строки — 74 октета, переносы корректные, все обязательные поля на месте.

## 7. Что честно остаётся демо

- Нет бэкенда: «Купить билет» — метка с ценой, а не переход на платёж. Кнопка не притворяется ссылкой.
- Организаторов, отзывов и рейтингов в данных нет — соответствующие блоки не рисуются, чтобы не показывать пустые обещания.
- Даты считаются от сегодняшнего дня при загрузке; для реального продукта нужен API-источник событий.
